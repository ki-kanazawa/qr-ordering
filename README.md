# こまち食堂 · QRコード注文

お客様向けの注文ページと店舗スタッフ向けの管理画面を備えた、日本語対応のQRコード注文アプリです。メニュー、注文、店舗設定はSQLiteデータベースに保存されます。

## 主な機能

- **お客様向け注文ページ**：メニューのカテゴリー表示・検索、カートでの数量変更、テーブル選択、お名前・ご要望の入力、注文確定。
- **注文状況の確認**：最近の注文を確認できます。スタッフが注文状況を更新すると、お客様の画面にも自動で反映されます。
- **データベース**：SQLiteファイルに注文、注文明細、メニュー、店舗設定を保存します。初回起動時は既存の `data/restaurant.json` があれば自動で移行します。
- **不正注文対策**：注文APIは接続元ごとに10分間で最大10回、管理ログインは15分間で最大5回に制限します。同じ注文の再送信は一度だけ記録し、数量と価格はサーバー側で検証します。
- **店舗管理画面**：パスワードログイン、注文一覧・注文状況の更新、本日の注文数と売上の集計。
- **メニュー管理**：メニューの追加・編集・販売停止・削除。
- **メニュー写真**：JPG・PNG・WebP形式の写真を1枚5MBまでアップロードし、お客様向けメニューに表示できます。
- **店舗・テーブル管理**：店舗名とお知らせの設定、テーブル番号の管理、テーブルごとのQRコード生成・SVGダウンロード・印刷。
- **レスポンシブ対応**：スマートフォンとデスクトップのブラウザーで利用できます。

## 起動方法

Node.js 18 以上が必要です。

```bash
npm install
npm start
```

ブラウザーで以下を開いてください。

- お客様向け注文ページ：<http://localhost:3000>
- 店舗管理画面：<http://localhost:3000/admin>

初回起動時に `data/restaurant.sqlite` が作成されます。既存の `data/restaurant.json` がある場合は設定・メニュー・注文をSQLiteに引き継ぎます。JSONファイルは移行後もそのまま残ります。

SQLiteデータベースの保存先を変更する場合は `.env` に `DATABASE_PATH` を設定してください（例：`DATABASE_PATH=./data/restaurant.sqlite`）。Node.js内蔵のSQLite APIがないNode.js 18以降でも利用できます。

## 管理者設定と公開

管理画面の初期パスワードは `246810` です。公開前にプロジェクトフォルダーへ `.env` ファイルを作成し（`.env.example` を参照）、`ADMIN_PASSWORD` に独自のパスワードを、`SESSION_SECRET` に十分長いランダムな文字列を設定してください。`SESSION_SECRET` を指定しない場合、ローカル起動時はサーバーの起動ごとにセッションキーが生成されます。

お客様がスマートフォンでQRコードを読み取って利用するには、スマートフォンからアクセスできるアドレスでサーバーを公開し、`.env` に次のように設定してください。

```dotenv
PUBLIC_URL=https://example.jp
```

`PUBLIC_URL` を設定しない場合、QRコードには管理画面を開いたときのホスト名が使用されます。パソコン上の `localhost` は別のスマートフォンからアクセスできません。同じLAN内で利用する場合は、パソコンのLAN内IPアドレスとポート番号を設定してください。

## お支払いについて

注文のお支払い方法は「店頭払い」です。管理画面では注文金額と注文状況を管理できますが、オンライン決済は実装されていません。実際のオンライン決済には、決済事業者との契約および決済通知・秘密鍵・入金照合の設定が別途必要です。

## データのバックアップ

サーバーを停止してから `data/restaurant.sqlite`、必要な場合は移行元の `data/restaurant.json`、および `data/uploads/` をバックアップしてください。店舗情報・注文・メニュー写真が保存されています。お客様の注文情報を含む本番データは、バージョン管理に登録しないでください。

### 不正注文対策の設定

注文は接続元IPアドレスごとに10分間で最大10回、管理画面へのログイン試行は15分間で最大5回です。注文には一意な冪等性キーを使い、通信再試行による二重注文を防ぎます。メニュー価格はブラウザーから受け取らず、データベース上の価格で合計を計算します。1回の注文は合計50品までです。

複数のNode.jsプロセスや複数サーバーを同時に起動する場合は、SQLiteとプロセス内レート制限では十分でありません。その場合はPostgreSQLなどの共有DBと共有レート制限ストアへの移行を検討してください。信頼できるリバースプロキシの背後で運用する場合のみ、実際のプロキシ段数に合わせて `TRUST_PROXY_HOPS` を設定してください。信頼できないプロキシ値をそのまま信頼するとIP制限を回避されるおそれがあります。
